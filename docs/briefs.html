Food, hunger, starvation V1

FEATURE_FOOD_HUNGER_STARVATION_V1_GROK_BUILD_BRIEF.md

Metadata
FieldValue

Feature / versionDwarf Food meter + starvation damage/death + grilled mushroom cook production (Kitchen / Fireplace) V1
EngineerGrok Build (sole coder)
ArchitectHuman (Colin) — approvals and acceptance
ProductUnderground Kingdom (Unity / C#)
Unity project rootUnity project root

Architect intent (excerpt)

  1. Dwarfs have a Food meter (0–100). 100 = fully fed; 0 = starving. Avoid “hunger bar” wording.
  2. Meter drains over sim time; at 0, dwarfs take HP damage at the same pace and can die.
  3. Starvation damage ignores defense.
  4. Only dwarfs are affected (not enemies or buildings).
  5. Add one food item: Grilled Mushroom (restores +20 Food when eaten later).
  6. Drinks (ale) do not affect the Food meter.
  7. Kitchen and Fireplace can cook grilled mushroom via order-based production, output in building output slots.
  8. Eating / auto-eat / consume API was out of scope for this V1 session — restore value is content for the item.

Goal (one paragraph)

Introduce a per-dwarf Food need (0–100, start full) that drains at 1 point per 10 sim-seconds and, at 0, applies 1 HP per 10 sim-seconds with defense ignored, using the existing death pipeline when HP reaches 0. Add content item grilled_mushroom. Enable order-based cooking at Kitchen and Fireplace: consume cave_mushroom from building input slots, after 5 s per unit write grilled mushroom into building output slots. Show Food X/100 on dwarf Inspect; persist Food in agents save/load. No auto-eat AI and no consume API in V1.

Later accepted as UK-FEAT-FOOD-HUNGER-STARVATION-V1 (4 Aug 2026). Auto-eat followed in a separate slice the same day.

Status (as written)Brief delivered. Gate B starts only when the Architect explicitly starts it. No production code until Architect approves the Gate B plan.

Architect intent (excerpt)

  1. Pathfinding must walk the standable volume (±X, ±Z on a floor), not only the 2D slice.
  2. Keep New Game 2D-playable: add a volume path API; do not replace the live mover graph yet.
  3. Do not put live dwarves on Z in this task. Tests and the new API prove XZ routes (including front→back 4 hops on a depth-5 hallway).
  4. Ladders / ramps / changing feet Y stay out.

Goal (one paragraph)

Add volume pathfinding that searches standable cells: 4-neighbors ±X and ±Z at the same feet Y; 1 tile X = 1 tile Z. Keep all existing 2D FindPath / FindNearestWalkable overloads behaviorally unchanged for live Labor and colonists. New overloads take feet (x, y, z) and use IsStandable only. CapExceeded 1000. EditMode tests: X hallway, Z hallway, depth-5 front→back is 4 hops and not 3. Do not move AgentMotor or the 2D view onto Z.

Later accepted as UK-FEAT-VOLUME-PATHFINDING-V1 (17 Aug 2026).

Inspection tool V1

FEATURE_INSPECTION_TOOL_V1_GROK_BUILD_BRIEF.md

Metadata
FieldValue
Task IDUK-FEAT-INSPECTION-TOOL-V1
Feature / versionUnified world inspection: rotating tile stack, blue highlight, 3-section info windows V1
EngineerGrok Build (sole coder)
ArchitectHuman (Colin) — approvals and acceptance
Unity project rootUnity project root

Architect intent (excerpt)

  1. Players need an inspection tool that shows information about things in the game world, with type-specific content and actions.
  2. Left-click a world object/tile (in default navigate) opens inspection for that tile’s stack.
  3. Rotating selection cycles multiple objects on the same grid tile (e.g. dwarf on plant on cave).
  4. Selected tile and selected object use a blue border; a list of stack objects appears under the tile.
  5. An info window (header / content / interaction) appears for the selected object — one window at a time.

Goal (one paragraph)

Replace fragmented world-click selection (dwarf-first priority, separate plant dump, no enemies/sites/terrain stack) with a unified default-navigate inspection system: LMB builds a rotating stack of inspectable objects on a fog-visible tile, highlights the tile and active object in blue, shows an under-tile object list, and opens a single fixed left-side 3-section info window per selected type — with harvest/dig actions from plant/resource panels and existing dwarf/building interactions retained (minus Deselect buttons; RMB dismisses).

Later accepted as UK-FEAT-INSPECTION-TOOL-V1 (31 Jul 2026).
