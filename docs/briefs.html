1. Architect intent (non-normative summary)

  1. Dwarfs have a Food meter (0–100). 100 = fully fed; 0 = starving. Avoid “hunger bar” wording (full hunger is contradictory).
  2. Meter drains over sim time; at 0, dwarfs take HP damage at the same pace and can die.
  3. Starvation damage ignores defense.
  4. Only dwarfs are affected (not enemies, moles, buildings).
  5. No edible food items exist today → add one: Grilled Mushroom (ItemCatalog consumable; restores +20 Food when eaten later).
  6. Drinks (ale) do not affect the Food meter.
  7. Kitchen and Fireplace can cook grilled mushroom via order-based production (forge-like), with output landing in building output slots.
  8. Eating / auto-eat / consume API is out of scope this session — Food restore value is content for the item; no runtime eat path required yet.
  9. Architect direction: consider a shared building production path (forge-like I/O orders, reusable for future craft buildings).

3. Goal (one paragraph)

Introduce a per-dwarf Food need (0–100, start full) that drains at 1 point per 10 sim-seconds and, at 0, applies 1 HP per 10 sim-seconds with defense ignored, using the existing death pipeline when HP reaches 0. Add content item grilled_mushroom (display Grilled Mushroom, food consumable, +20 Food restore when a future eat path exists). Enable order-based cooking at Kitchen and Fireplace: consume cave_mushroom from building input slots, after 5 s per unit write grilled mushroom into building output slots, reusing forge-like order / haul / labor patterns (optionally via a shared production collaborator). Show Food X/100 on dwarf Inspect; persist Food in agents save/load. No auto-eat AI and no consume API in V1.

5. In scope (concrete deliverables)

# Deliverable

A1 Per living colonist Food value: range 0–100, constant max 100.
A2 Spawn (primary + additional): start at 100 (fully fed).
A3 Sim tick (pause-respecting): while Food > 0, accumulate time and apply −1 Food per 10.0 sim-seconds (same pacing style as other accumulators; fractional remainder OK).

B1 Add grilled_mushroom to ItemCatalog: display Grilled Mushroom.
B2 Extend item model as needed: e.g. ItemType.Food (or Consumable) + FoodRestoreAmount = 20. Preferred equip slot = consumable slots (for future equip/use).
B3 No runtime eat / consume / auto-use path in V1 (Q11). Restore amount is data only.
B4 Document that ale and all drinks do not affect Food; raw cave_mushroom / darkcap are not edible Food items for this system.

C1 Give Kitchen and Fireplace local input/output inventories (init on construct / starter place / upgrade finalize as applicable).
C2 Order-based cooking (forge-like): player creates cook orders for grilled mushroom; dwarf labor processes units; queue/hold patterns may mirror forge where reuse is natural.

C4 Output destination: produced food lands in that building’s output slots only (not global Economy auto-credit). No auto-export to stockpile in V1 (same spirit as forge outputs).
C5 Input logistics: spawn AUTO_DELIVER hauls of cave_mushroom into building input with capacity reservation (reuse forge haul/reserve patterns; multi-resource packer where applicable).
C6 Both Kitchen and Fireplace support the same grilled-mushroom cook order (Fireplace is non-upgradable; Kitchen multilevel — same recipe all kitchen levels unless locks say otherwise).

11. Manual verification steps (Architect)

  1. Drain: New Game → Inspect starter dwarf → note Food 100/100 → unpause ~30–40s → Food should drop by ~3–4.
  2. Starvation: Debug or long wait to Food 0 (or temporary test hook if Coding adds debug-only set Food — not a player eat API) → confirm HP ticks down every 10s; equip high defense gear if available and confirm starvation still damages full HP.
  3. Death: Allow starvation to 0 HP → dwarf dies; tasks free; no soft-lock.
  4. Cook — Fireplace: Select free fireplace → order grilled mushroom ×5 → ensure cave_mushroom stock exists → haulers fill inputs → dwarf processes → grilled mushroom appears in fireplace output slots (~5s per unit).
  5. Cook — Kitchen: Build kitchen → same order path → output slots fill.
  6. Inspect: Food line visible on dwarf panel.
  7. Save/load: Mid-drain and mid-cook → save → load → Food and cook progress/inventories sensible.
  8. Sanity: Forge order steel still works; dig/harvest/build unaffected; drinks stock irrelevant to Food.
