BriefFEATURE_VOLUME_DIG_MARKS_V1_GROK_BUILD_BRIEF.md
StatusImplemented

Restated goal

Volume DIG marks sit on the z = 0 cutaway, in front of the earth voxel, facing the dollhouse camera. Dig stays XY. Do not put marks on the chamber back. Harvest/build marks stay as they are.

In scope / out of scope

In: a pure WorldVolumeDigMarkPose helper (XY → position + rotation); Dig uses that pose; unlit mark, no collider; EditMode pose tests without GPU; Presentation README + decisions.

Out: chamber-back marks; dig at z > 0; harvest/build polish; V1/V3–V5; cutover; art; 2D overlay into Volume; Task XY / dig sim / save format.

Architecture notes

Why z = 0.07 failed (verified at implement): earth columns are Solid for z in [0,1). Center (x+0.5, y+0.5, 0.07) sits inside the voxel; the cutaway face is at z = 0. Camera pitch 18° looks +Z. Facade lock: z = −0.05, identity rotation so the quad faces the camera. Wiring was already bound — this was pose, not a missing Bind.

Accepted 1 Sep 2026 (UK-FEAT-VOLUME-DIG-MARKS-V1).

Depth-1 occupy z = 0 Implemented

FEATURE_VOLUME_DEPTH1_OCCUPY_Z0_V1_CODING_PLAN.md · 2026-08-30 · class complex

Header
FieldValue
Task IDUK-FEAT-VOLUME-DEPTH1-OCCUPY-Z0-V1
StatusImplemented
Classcomplex

Restated goal

Depth-1 stamps occupy z = 0 of their XY column. Volume World colonists use per-voxel occupy so they can walk z ≥ 1 behind a wall or locked door in a d = 5 hall and continue. Floors stay illegal as feet on the slab at any z. 5-deep solid cells still block all z. Enemies / bash stay XY. Do not flatten d. Do not raise MaxExpansions. Do not keep 2D-then-lift as the only colonist volume planner.

In scope / out of scope

In: IVolumeWalkabilityMap + VolumeWalkRules; BuildingService.IsMovementPassable(x, y, z, isEnemy); FindColonistVolumePath uses volume A* first; motors/spawn inherit; 2D 1×2 and enemy maps unchanged; EditMode tests; READMEs.

Out: flatten d; raise the 1000 expansion cap; floor tiles occupy-legal; enemy behind-wall; 5-deep interiors; delete 2D scene; save bump; V4/V5/F/G.

Architecture notes

Why XY IsWalkable cannot stay the volume gate: stamps do not write d. A wall on a d = 5 tunnel is still Air at z ≥ 1. VolumeLiveStep.CanOccupy ANDed walkability.IsWalkable(x, y) for every z → the column was dead. Fix occupy, then search the volume graph. Pathfinding must not reference Buildings — World grows IVolumeWalkabilityMap; Session’s ColonistWalkabilityMap implements it.

Accepted 1 Sep 2026 (UK-FEAT-VOLUME-DEPTH1-OCCUPY-Z0-V1).

Ladder path fix V1 Approved

FEATURE_VOLUME_LADDER_PATH_FIX_V1_CODING_PLAN.md · 2026-08-26 · class advanced

Header
FieldValue
Task IDUK-FEAT-VOLUME-LADDER-PATH-FIX-V1
StatusApproved — implementing
Classadvanced

Restated goal

Make Volume World colonist move and Labor walks climb stacked completed ladders to an occupy-legal upstairs goal, including in a d=5 hall that also has walls/floors/doors. The 2D 1×2 dwarf graph used as the climb skeleton must expand only cells that are volume-occupiable at z = 0: IsLiveStandable(x, y, 0, ladders) and walkability.IsWalkable(x, y). Keep FindColonistVolumePath as 2D-then-lift (3D A* stays fallback only). Volume move pick must pass the ladder query and skip non-occupy-legal cells so a floor slab is not a stand goal.

In scope / out of scope

In: FootprintPassability 1×2 + volume predicate; keep 2D-then-lift; Volume move pick occupy-legal; EditMode tests including a wall on the slice; README one-liners. Labor inherits via existing FindColonistVolumePath.

Out: re-flatten structure d; raise MaxExpansions as the fix; replace 2D-then-lift with a 3D-only colonist planner; live Z on 2D Gameplay; Phase F; making floor tiles occupy-legal.

Architecture notes

After stamps stopped flattening d, a wall/floor in a chamber keeps Air, so IsStandable is true while occupy still required XY IsWalkable. Lift died on the first wall; 3D fallback fanned out in d=5 and missed the climb. Proposed 1×2 + volume: legal feet iff live-stand at z=0 AND IsWalkable. GameplayComposer always constructs PathfindingService with a volume query — the same predicate in both 2D Gameplay and Volume World. That is not live Z on the 2D tilemap; motors stay z = 0 in Slice2D.

Honest status: this plan is Approved, not Implemented. The Volume product roadmap (26 Aug 2026) records E4 / ladder playtest as not accepted; V5 back-wall climb is the remaining upstairs path. No accept commit for this task ID is in the public log.
