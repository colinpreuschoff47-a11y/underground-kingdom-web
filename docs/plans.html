4. Architecture

4.1 Why XY IsWalkable cannot stay the volume gate

Stamps do not write d. A wall on a d = 5 tunnel is still Air at z ≥ 1. VolumeLiveStep.CanOccupy ANDs walkability.IsWalkable(x, y) for every z → the column is dead. 2D-then-lift cannot enter that XY cell. Fix occupy, then search the volume graph.

4.2 Volume-walk interface (Pathfinding must not reference Buildings)

World (sibling of IWalkabilityMap):

public interface IVolumeWalkabilityMap
{
    bool IsWalkable(int x, int y, int z);
}

public static class VolumeWalkRules
{
    public static bool IsWalkableAt(IWalkabilityMap walkability, int x, int y, int z)
    {
        if (walkability is IVolumeWalkabilityMap volumeWalk)
        {
            return volumeWalk.IsWalkable(x, y, z);
        }

        return walkability == null || walkability.IsWalkable(x, y);
    }
}

Fallback (frozen): XY-only maps (WorldService, EnemyPathWalkability, FixtureLadderWalk) keep today’s “XY false → all z illegal.” That is how enemies stay on XY law without a second A*.

VolumeLiveStep.CanOccupy / CanVisit: replace the XY IsWalkable(x, y) check with VolumeWalkRules.IsWalkableAt(..., z). Live-stand unchanged. Ladder ±Y still CanClimbY (exception z = 0).
