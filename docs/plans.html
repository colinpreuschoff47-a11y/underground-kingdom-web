  1. Buried: earth columns are Solid for z ∈ [0,1). Center (x+0.5, y+0.5, 0.07) is inside the voxel; the cutaway face is at z = 0.

Wiring is already bound; this is pose, not a missing Bind.

4. Architecture

4.1 Why XY IsWalkable cannot stay the volume gate

Stamps do not write d. A wall on a d = 5 tunnel is still Air at z ≥ 1. VolumeLiveStep.CanOccupy ANDs walkability.IsWalkable(x, y) for every z → the column is dead. 2D-then-lift cannot enter that XY cell. Fix occupy, then search the volume graph.

4.2 Volume-walk interface (Pathfinding must not reference Buildings)

World (sibling of IWalkabilityMap):

public interface IVolumeWalkabilityMap
{
    bool IsWalkable(int x, int y, int z);
}

public static class VolumeWalkRules
{
    public static bool IsWalkableAt(IWalkabilityMap walkability, int x, int y, int z)
    {
        if (walkability is IVolumeWalkabilityMap volumeWalk)
        {
            return volumeWalk.IsWalkable(x, y, z);
        }

        return walkability == null || walkability.IsWalkable(x, y);
    }
}

Fallback (frozen): XY-only maps (WorldService, EnemyPathWalkability, FixtureLadderWalk) keep today’s “XY false → all z illegal.” That is how enemies stay on XY law without a second A*.

VolumeLiveStep.CanOccupy / CanVisit: replace the XY IsWalkable(x, y) check with VolumeWalkRules.IsWalkableAt(..., z). Live-stand unchanged. Ladder ±Y still CanClimbY (exception z = 0).

Same helper: VolumeSpawnFeet.IsOccupy, WorldVolumeColumnPick.TryRayToStandableFeet (replace walkability.IsWalkable(x, y)).

4.3 Depth-1 vs floor vs door vs 5-deep (Buildings)

Content helper (ids already in StructureFunctionConstants / BuildingCatalog.FireplaceId):

IsDepth1VolumeOccupant(typeId) ⇔ wall | door | ladder | trap | floor | fireplace

IStructurePassabilityQuery adds:

bool IsMovementPassable(int x, int y, int z, bool isEnemy);

Keep IsMovementPassable(x, y, bool isEnemy) as the 2D / enemy API.

Implementation in BuildingService:

  1. isEnemy == true: ignore z; existing XY body (walls never; locked/Auto per DoorAllowsMover; floors never; ladders on-cell; construction solid never). Enemies do not walk behind.
  2. isEnemy == false (colonists):
    - Resolve type at cell: completed building (TryGetBuildingAt) else new-build site (TryGetSiteAt → BuildingTypeId). Upgrade-hidden building: fall through to terrain (5-deep solid stays all-z).
    - Floor (completed or site): false at any z.
    - z >= 1 and IsDepth1VolumeOccupant and not floor: true (structure occupies z = 0 only; live-stand is Pathfinding’s job).
    - Else existing XY body (z == 0 or 5-deep / generic BuildingSolid / ConstructionSiteSolid without a depth-1 type).

z = 0 colonist result must match today’s XY method (wall false, locked door false, Open/Auto DoorAllowsMover, ladder true, floor false, trap/fireplace unchanged walkable, storage solid false).

Do not invent trap/fireplace blocking. Do not make 5-deep interiors walkable.

XY overload: may delegate to (x, y, z: 0, isEnemy) once the z = 0 branch is identical.

4.4 Session bind

ColonistWalkabilityMap : IWalkabilityMap, ILadderCellQuery, IVolumeWalkabilityMap

  • IsWalkable(x, y) — unchanged (structures XY, isEnemy false).
  • IsWalkable(x, y, z) → IsMovementPassable(x, y, z, isEnemy: false).

GameplayComposer already constructs PathfindingService(ColonistWalk, World, World) and SetMovePickQueries(ColonistWalk, ColonistWalk). No new composer services.

4.5 FindColonistVolumePath (R17)

Today: 2D 1×2 first; lift; fallback volume A* (still XY-gated). Behind-wall 2D fails; 3D also fails.

This slice:

if !IsVolumePassable(start) → NonWalkableStart
if !IsVolumePassable(goal)  → NonWalkableGoal
if start == goal            → [start]
volume = FindPath(startFeet, goalFeet)   // 3D A*, per-voxel occupy, cap 1000
if volume.IsSuccess         → volume
// supplement only — must not run first
return TryLiftDwarfSlice(2D 1×2) ?? volume  // keep volume’s Blocked/CapExceeded if lift fails
  • Volume A first* so a goal at (wallX, wallY, z≥1) is searched on the per-voxel graph (2D goal XY is non-walkable, so lift-first would never be the behind-wall success).
  • 2D-then-lift only after Blocked/CapExceeded → stacked z = 0 ladders on small maps can still succeed; cannot hide a behind-wall success.
  • FootprintPassability 1×2 unchanged (occupy at z = 0 + XY). 2D Gameplay unchanged.
  • MaxExpansions stays 1000. If the exit behind-wall fixture (short hall, one wall, start/goal adjacent columns) returns CapExceeded: STOP, report, do not raise the cap.

4.7 Ejection (F8)

UnitDisplacementService colonist loop: use c.Feet, not only c.Position.

  • If blocked XY contains the tile and !IsMovementPassable(feet.x, feet.y, feet.z, false) → eject (z = 0 on a new wall).
  • If feet z ≥ 1 still occupy-legal → do not eject.
  • Eject dest stays nearest XY free stand (SetPosition(Vector2Int) → z = 0). Fine for z = 0 victims.
  • Enemies / moles: still XY blocked.Contains(Position).

Tests must pass IStructurePassabilityQuery into UnitDisplacementService (production already does; UnitDisplacementServiceTests currently passes null — fix when adding F11(i)).
