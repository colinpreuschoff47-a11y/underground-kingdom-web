The pipeline

Quoted and adapted from the project’s AGENTS.md and pipeline kickoffs. Briefs are delivered, not approved. Gate B starts only when the Architect explicitly says “start Gate B.”

  1. Prompt Architect states a plain-language idea (German or English). Incomplete is fine. Brief Writer must ask when numbers, scope, or player-facing behavior are unclear — and must not invent game rules.
  2. Brief Writer → FEATURE_* brief Grok Build, in Brief Writer mode, turns the idea into a task brief under architecture_docs/briefs/features/. Naming: FEATURE_<SHORT_NAME>_V1_GROK_BUILD_BRIEF.md. A Coding Agent kickoff block is pasted in chat. Then STOP. Do not start Gate B.
  3. Architect says start Gate B Silence is not permission. “Brief written” is not permission. The instruction applies to that task only.
  4. Gate B Phase 1 — coding plan (no code) Restate the goal. List in/out of scope. Propose architecture, APIs, risks. Write the full plan to architecture_docs/coding_plans/. Present it in chat. Chat-only plans are a process fail. Then STOP and wait.
  5. Architect approves the plan If edits are requested, patch the same plan file and STOP again. Phase 2 implements the plan file, not a remembered chat summary.
  6. Phase 2 — implement Touch only files required for the task. Keep changes localized. Do not redesign unrelated systems. Do not change public APIs or save formats unless the approval included that.
  7. Phase 3 — validation Report what changed, why, how to verify, side effects, docs updated, and optional suggestions that must not be implemented. Then STOP.
  8. Architect accept Play-test and accept the completed slice. Validation report alone is not acceptance.
  9. Git commit + push Engineer commits at the Unity project root and pushes to origin after explicit accept. Then STOP. Do not start the next phase unless tasked.

Difficulty classes

Before writing a FEATURE_* / PERF_* brief and before starting Gate B Phase 1, the Engineer must classify the coding task and state the class in the first reply. When unsure, pick the harder class. If the task touches World volume, path graphs, save format, or a public interface, the class is at least advanced.

AGENTS.md — task difficulty (LOCKED)
ClassTypical meaningBrief?
Very simple One obvious, local change: a locked constant, a typo, a single-file wiring already specified. No new public API, module, or save/spatial/pipeline change. No brief. Engineer states the class and proceeds with Gate B Phase 1 in the same turn.
Simple Localized coding, few files, existing APIs, no new cross-module contract. Ask whether a brief is required, then STOP until the Architect answers.
Advanced New or changed public API, several modules, new sim/presentation contract, or a roadmap slice with real design surface. Brief always required. Write it, then STOP. Do not start Gate B until explicitly told.
Complex Cross-cutting space/save/path/render change, many modules, or a cutover. Brief always required. Same stop rule as advanced.

What a brief is for

The Brief Writer’s one job is a complete task brief plus a ready-to-paste Coding Agent kickoff. It does not implement game features. It does not write a Gate B plan — that is the Coding session’s job. Gold briefs use tables, hard forbids, testable exits, and a “do not rebuild” baseline.
